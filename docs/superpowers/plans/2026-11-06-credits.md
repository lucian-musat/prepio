# Credits Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Students spend credits on checks done by the „profesorul digital” (AI evaluation). They get welcome credits once, buy packages (approved instantly, no payment), and admins manage costs, packages and student balances.

**Architecture:**
- **Postgres holds the money logic.** `profiles.credit_balance` and the append-only `credit_ledger` are changed only by security-definer functions.
- **The admin app's API routes are the only spenders.** The evaluate route spends before the AI call and refunds on failure; a new purchase route approves orders.
- **Student app:** a `CreditsProvider` holds the balance. A credit gate in the exercise screens opens `BuyCreditsSheet` over the exercise, so the typed answer is never unmounted.

**Tech Stack:**
- Supabase: Postgres, RLS, pgTAP, pgcrypto `hmac`.
- Admin: Next.js App Router, react-bootstrap, vitest, Playwright.
- Student app: Expo / React Native (+ web), jest.
- `@prepio/shared` for the logic shared by both apps.

**Spec:** `docs/superpowers/specs/2026-11-06-credits-design.md`. Mockups: `docs/design/2026-11-06-credits-balance-mockup.html` and `docs/design/2026-11-06-credits-purchase-mockup.html`.

Run every command from Windows as `wsl -d Ubuntu-22.04 -- bash -ic "cd ~/projects/prepio_new && <cmd>"`. Below, only `<cmd>` is shown.

## Global Constraints

- The student UI never shows the word "AI". The feature is „Verificare cu profesorul digital”; the currency is „credite”. Exception: the privacy screen.
- AI types are exactly `facts`, `comparison`, `viewpoint`, `argument`, `essay` (`AI_TYPES`).
- `credit_cost` is an integer from 1 to 5. Defaults: facts 1, viewpoint 1, comparison 2, argument 2, essay 1 **per requirement**.
- Essay costs: „Verifică cerința” = `credit_cost`; „Verifică eseul întreg” = `credit_cost × requirements.length`.
- Welcome credits: `credit_settings.welcome_credits`, start value **12**, range 0–1000. Granted once per email, also after the account is deleted and re-created.
- Starting packages: **20 credits / 999 bani, 50 / 1999 (featured), 120 / 3999**. Prices are stored in bani and shown as `19,99 lei`.
- The balance is never negative. Every change writes a `credit_ledger` row carrying `balance_after`.
- No charge when a request is rejected before the spend (validation, not found, rate limit). After the spend, any failure refunds in the same request, best effort.
- The order is: rate limit → spend → AI. The existing limits (30 per hour per user, 300 per day globally) stay.
- Packages are never deleted, only deactivated. At most one active package is featured.
- The Romanian plural uses the „de” rule (`plural()`): „1 credit”, „2 credite”, „20 de credite”.
- DB rules from `docs/database-migrations.md`: a new migration via `pnpm db:new`, RLS on every new table, pgTAP tests. Never edit an applied migration.
- Code, comments and commits are in English; UI copy is in Romanian, exactly as written here.

## Review Focus

1. **Two checks racing for the last credit.** This happens with two essay requirements checked at once, or a double tap. Exactly one is charged; the other gets 402 and opens the sheet, and both texts stay. Pinned by the pgTAP "spend to zero" test (Task 1) and the `EssayInput` race test (Task 10).
2. **A balance stale across devices.** Example: credits bought on the web while the phone still shows the old number. A 402 body updates the chip, and the balance is refetched when the app returns to the foreground. Pinned in Task 9 (`CreditsProvider` tests) and Task 10 (402 sets the balance).
3. **The exercise was edited after the client computed the cost** (requirement count, cost). The server's `required` wins in the sheet text. Pinned in Task 3 (402 uses the server cost) and Task 10 (the sheet shows `e.required`).
4. **Re-registering with a differently-cased or padded email** („ Ion@Gmail.com ”). No second welcome grant. Pinned in Task 2 (pgTAP).
5. **A package deactivated while the sheet is open.** The purchase answers 409 `package_unavailable`, then the sheet reloads the packages and shows „Pachetul nu mai este disponibil. Alege altul.” Pinned in Task 4 (route) and Task 10 (sheet).

### Task 1: Credits schema and functions

**Files:**
- Create: `supabase/migrations/<ts>_credits.sql` (via `pnpm db:new credits`)
- Create: `supabase/tests/credits.test.sql`

**Interfaces:**
- Produces, as tables:
  - `profiles.credit_balance int not null default 0 check (credit_balance >= 0)`. Students have select only; there is no update grant on it.
  - `credit_settings(id int pk check (id = 1), welcome_credits int not null default 12 check (welcome_credits between 0 and 1000))`, seeded with row 1.
  - `credit_packages(id uuid pk default gen_random_uuid(), credits int not null check (credits between 1 and 10000), price_bani int not null check (price_bani between 1 and 10000000), featured bool not null default false, active bool not null default true, sort_order int not null default 0, created_at timestamptz not null default now())`, plus a unique index `on credit_packages ((true)) where featured and active`. Seeded with the 3 starting packages, `sort_order` 0, 1, 2.
  - `credit_orders(id uuid pk default gen_random_uuid(), user_id uuid not null references auth.users on delete cascade, package_id uuid not null references credit_packages on delete restrict, credits int not null, price_bani int not null, status text not null check (status in ('pending','approved','failed')), provider text not null default 'none', provider_ref text, created_at timestamptz not null default now(), approved_at timestamptz)`.
  - `credit_ledger(id bigint generated always as identity pk, user_id uuid not null references auth.users on delete cascade, delta int not null check (delta <> 0), balance_after int not null check (balance_after >= 0), kind text not null check (kind in ('welcome','purchase','check','refund','admin')), exercise_id uuid references consolidation_exercises on delete set null, target text, order_id uuid references credit_orders on delete set null, admin_id uuid references auth.users on delete set null, refund_of bigint unique references credit_ledger, reason text, created_at timestamptz not null default now())`.
    - Constraint: `kind <> 'admin' or btrim(coalesce(reason,'')) <> ''`.
    - Indexes: `(user_id, id desc)`, and a unique `(user_id) where kind = 'welcome'`.
    - `target` is `'exercise' | 'whole' | 'req:<requirementId>'`.
  - `consolidation_exercises.credit_cost smallint not null default 1 check (credit_cost between 1 and 5)`, backfilled to 2 where `type in ('comparison','argument')`.
- Produces, as RLS:
  - Students: select their own `credit_ledger` and `credit_orders` rows, and `credit_packages` where `active`.
  - Admins (`is_admin()`): select on all four tables, plus update on `credit_settings`.
  - Nobody writes the ledger or orders directly.
- Produces, as functions (all `security definer`, `set search_path = ''`, `revoke execute … from public, anon, authenticated`):
  - `spend_credits(p_user uuid, p_amount int, p_exercise uuid, p_target text) returns table(entry_id bigint, balance int)`, service_role only.
    - It uses one `update … where credit_balance >= p_amount returning`.
    - When the update matches nothing, it returns `(null, current_balance)`.
  - `refund_credits(p_entry bigint) returns int` (the new balance), service_role only.
    - It inserts a `refund` row with `refund_of = p_entry` and `delta = -original.delta`.
    - It is idempotent: a second call returns the balance and inserts nothing.
  - `purchase_credit_package(p_user uuid, p_package uuid) returns table(order_id uuid, credits int, balance int)`, service_role only.
    - It snapshots the package into an `approved` order (`approved_at = now()`) and writes a `purchase` ledger row.
    - For a missing or inactive package it raises `raise exception 'package_unavailable' using errcode = 'P0001'`.
  - `admin_adjust_credits(p_user uuid, p_delta int, p_reason text) returns int`, granted to authenticated.
    - Without `is_admin()` it raises errcode `42501`.
    - A blank reason raises `'reason_required'`; `p_delta = 0` raises `'bad_delta'`; a result below 0 raises `'insufficient_balance'` (all with errcode `P0001`).
    - It writes an `admin` row with `admin_id = auth.uid()`.
  - `admin_save_credit_settings(p_welcome int, p_packages jsonb) returns void`, authenticated with an `is_admin()` check.
    - `p_packages` is an array of `{id?, credits, price_bani, featured, active}`; array index = `sort_order`.
    - It updates the existing ids, inserts the rows without one, and never deletes. Packages missing from the array keep their row.
    - It runs in one transaction: clear `featured` first, then apply, so the unique index never trips mid-save.
  - `admin_students(p_search text, p_limit int, p_offset int, p_id uuid default null) returns table(id uuid, display_name text, email text, credit_balance int, created_at timestamptz, total bigint)`, authenticated with an `is_admin()` check.
    - It excludes users present in `admins` and matches `p_search` with `ilike` on the name or email.
  - `admin_credit_ledger(p_user uuid, p_limit int, p_before bigint default null) returns table(id bigint, delta int, balance_after int, kind text, target text, reason text, created_at timestamptz, exercise_id uuid, exercise_type text, exercise_prompt text, admin_email text)`, admin only.
  - Internal: `public.credit_apply(p_user uuid, p_delta int, p_kind text, p_exercise uuid, p_target text, p_order uuid, p_admin uuid, p_reason text, p_refund_of bigint) returns table(entry_id bigint, balance int)`. It is the only writer of the balance and the ledger, executable by nobody but the functions above. It locks the profile row with `for update`.
