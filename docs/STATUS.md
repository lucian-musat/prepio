## Decisions taken during implementation (not in the original spec)

- Design system (spec `docs/superpowers/specs/2026-10-31-design-system-design.md`, doc `docs/design-system.md`): variant B "Mentă Prietenoasă" chosen by the owner; tokens in `packages/shared/src/theme.ts`; fonts Nunito + Nunito Sans (family keys CSS-safe in `apps/mobile/src/theme/fonts.ts`, react-native-web writes `fontFamily` unquoted). The old archive theme (Lora, Source Sans, parchment/bordeaux/gold) is removed.
- Primary is the darker teal `#0F766E` (white label 5.5:1) instead of the prototype's `#0D9488` (3.7:1) for AA; medium/accent text `#8A6A00`, feedback text `#1A7C49` / `#A54042`. Gradients keep the prototype colours.
- Student app uses an own UI kit (`apps/mobile/src/ui/`) instead of React Native Paper, whose Material look fought the design; Paper is removed.
- New native modules: `react-native-svg` (icons, score ring) and `expo-linear-gradient` (hero, progress bar). No `expo-updates`, so a new APK is required.
- Admin keeps Bootstrap 5 / react-bootstrap; the tokens are mapped to Bootstrap CSS variables in `apps/admin/src/app/theme.ts` (calm: no 3D/confetti/springy motion).
- Motion: in-flow enter animations use shared-value `Enter`/`useEnter`, not Reanimated `Keyframe` `entering` (on react-native-web 4.7.1 Keyframe leaves elements `position:absolute` with a frozen size). The prototype's outgoing-screen exit animation is not reproduced (the old screen/phase disappears at once on web; native uses the stack's `slide_from_right`) — would need to keep the previous phase mounted during the swap.
- Admin data access: functions in `apps/admin/src/lib/data/*.ts` taking a `SupabaseClient`; server actions are thin wrappers returning `ActionResult` (`{ok,error}`) with Romanian messages; every update/delete uses `.select('id')` and fails on 0 affected rows (RLS denials are silent otherwise).
- Rate limiting: fixed 1-hour window, 10 evaluations per IP, plus a global cap of 300/day (`consume_rate_limit`).
- `/api/evaluate`: per-request nonce delimiters around the student text (prompt-injection), 403 for foreign `Origin`, 415 unless JSON, `maxDuration = 60`.
- Seed is non-destructive by default (`SEED_RESET=1` replaces everything); DB-backed test suites refuse to run against non-local Supabase.
- Android package `dev.musat.prepio`; EAS keystore generated by EAS (stored in EAS credentials).
- Initial cloud schema + content were applied via the Supabase SQL editor; history repaired afterwards — all future changes go through `docs/database-migrations.md`.
- The POC was built directly on `main` (owner's choice at the time).
- Typed cards (2026-11-03; spec "Decisions made by Claude"): one `content` jsonb per card with TypeScript discriminated unions and a hand-written `validateCard` in `@prepio/shared`; `cardFromRow` is the only way untrusted JSON (DB rows, preview messages, `saveCard` input) becomes a `Card` and assigns deterministic, unique item ids (`point-<i>`, `cause-<i>`, `consequence-<i>`, `central`). The link preview's title is `content.pageTitle`, distinct from the optional card heading `title`.
- Formatted text is a small Markdown subset parsed by an own parser and rendered as native `Text` (never HTML); the admin edits it in a textarea with a toolbar.
- Preview fidelity: the admin embeds the real student code (`/preview` on the student web) in an iframe and posts the unsaved card; both sides check origin, source and message shape; `/preview` has a `frame-ancestors` CSP and needs no login.
- Video: `react-native-youtube-iframe` (WebView) on Android, a YouTube iframe on web; leaving the card unmounts the player. Links: `expo-web-browser` on native, a new tab (`Linking.openURL`, `noopener`) on web.
- Link metadata fetch (admin server action): http(s) only, every resolved address must be public, manual redirects re-checked (max 3), 5 s budget, 1 MB cap, `text/html` only. DNS-rebinding residual risk accepted (see backlog).
- Lesson 3 merged two pairs of text cards (titles became `### ` headings) to stay within 6–10 cards after adding video + link.
- Admin preview toggle labels are plain `Telefon` / `Desktop` (no emoji).
- Accessibility on web: react-native-web 0.21 ignores `accessibilityState`, so expanded/selected states use `aria-*` props; tappable images use the `button` role.
- The student app's only raw palette values (timeline line and key-dot ring, schema cause edge) are documented exceptions in `docs/design-system.md`.
- Learning modes (2026-11-04; spec "Decisions made by Claude", owner to check): progress is stored server-side in the student's account (`lesson_progress`), not on the device; correctness is checked in the app, no server-side grading (a student could write their own progress rows through the API — accepted, it only affects their own learning); `learning_mode` is nullable and `null` sends the student to the mode screen, so existing accounts see it once; the start screen appears in both modes every time a lesson is opened; the guided failure screen lists the wrong questions by number; locked lessons are visible (dimmed, 🔒), not hidden; a finished lesson can always be redone and redoing never un-finishes it; resuming restores the answers of the current attempt. From the review: a lesson with no questions passes as soon as its end is reached; a saved position on a lesson locked after a free → guided switch is kept but unreachable until it unlocks; redoing a finished lesson shows the normal result without „Ai deblocat”.
- Learning modes implementation: lesson order is the Home order flattened (sections in tree order, lessons by `position`); position saves (every step) never block the student and only log on failure, the finished mark blocks the result screen and offers „Reîncearcă” on failure; progress writes are serialised so a late position save can't land after the finished mark; `savePosition` upserts only `position`, so it never clears `finished_at`.

- Consolidation (2026-11-05; spec "Decisions made by Claude", owner to check): consolidation opens when the lesson is finished, in both learning modes, and never gates anything; only the latest attempt per exercise is stored in the account (no history), which the summary, „Reia doar ce nu a fost corect” and cross-device resume need; the essay has no separate introduction / conclusion fields and allows 1–6 requirements; runs („Reia…”) are tracked in `consolidation_runs`, restarting never deletes attempts, and returning to a completed consolidation opens its end screen; exercises that fail validation are hidden from students, and saving a source that detaches spans needs a confirmation; the AI context lives in the admin-only `consolidation_ai_context` table, while the answers for the deterministic checks are readable by the client (needed to check them); attempts use plain own-row RLS and the client stores the AI feedback (no anti-forgery work); at most two sources (A, B) per exercise; the old writing exercises became one-requirement essays (not deleted), and `/api/evaluate` and the grade settings went away (the `grade_min` / `grade_max` columns stay, unused); typo tolerance never applies to numbers, years, centuries or Roman numerals; the per-student AI limit is 30 per hour; the admin marks spans with native browser selection; the reading typeface is a serif (Literata); short-source threshold ~70 words; the verdict labels are exactly „Corect”, „Aproape”, „Mai lucrează”.
- Consolidation, taken during implementation: deleting a lesson removes its consolidation exercises first through a `BEFORE DELETE` trigger on `lessons` (the exercise → source link is `RESTRICT`, which would otherwise block the cascade); the essay requirement chip has a fifth state „Neverificat” (written but not checked yet, or edited since its check); „Încearcă din nou” on an essay keeps the texts and clears only the feedback (the spec said inputs clear; essays are long); the OpenAI structured-output schema is sent without `maxLength` (strict mode may not support it) and the server truncates the AI's strings instead; the model answer goes into the AI prompt as a teacher reference (the prompt tells the AI not to echo it); words in the source can't be marked with the keyboard on web (screen readers mark with tap-tap); a check judges only the first N marks / fields, and the student UI never offers more pens than N, so "mark everything" can't be „Corect”; a „Litera sursei” evidence span must lie in the correct source; when a mark could match several answer spans, a small bipartite assignment picks the best overall match; „Litera sursei” and the other deterministic checks run in the app, AI checks run on the server, which also recomputes the deterministic parts (marks, connectors) from the stored answer before prompting; facts / essay parts with an instant „no” (empty, too short, duplicate) never call the AI; the desktop action bar stays 720 px wide under the split (the mockup put „Verifică” in the right column, backlog); no `expo-haptics` (no new native module): the browser's vibration stands in on touch web, native gets no tick for now; `etc.`, `î.Hr.` and `d.Hr.` end a sentence only when the next word is capitalised (other abbreviations never do).
